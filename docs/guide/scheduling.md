# 每周定时运行

每个方案可按星期设置运行时间。先有人值守地跑通方案，再开启定时；AutoMAA 主 App 无需一直打开。

## 为方案设置时间

1. 打开方案编辑页，在“定时运行”中选择星期和时间。
2. 需要在其他星期使用不同时间时，点击“添加时段”；先从原时段取消对应星期。
3. 开启定时，等待界面显示已启用。

已启用方案修改星期或时间后会自动同步。关闭开关只取消当前方案的定时，不影响其他方案。模板中的轻量日常为每天 09:00、完整日常为每天 21:00，默认均未启用。

同一方案中，每个星期几只能属于一个时段。一天内需要执行不同任务组合时，创建不同方案；同一方案当天重复运行会跳过已成功的步骤。

## Mac 需要保持什么状态

| 到点时的状态 | 是否能运行 |
| --- | --- |
| AutoMAA 已退出，用户已登录、系统唤醒 | 后台 Runner 可以启动 |
| 显示器熄灭，系统未睡眠 | 可以运行 |
| 锁屏或停留在登录窗口 | 游戏图形操作不保证可用，不建议依赖 |
| 系统睡眠，包括合盖进入睡眠 | 不保证准时，通常在完全唤醒后补触发 |
| 用户已注销或 Mac 已关机 | 不会运行；关机期间错过的任务不会补回 |

需要准时执行时，接通电源，并在电池或节能设置中开启“显示器关闭时防止自动进入睡眠”。屏幕不必一直亮着，但不要将“网络访问唤醒”视为游戏自动化可用的保证。可参阅 [Apple 睡眠设置](https://support.apple.com/guide/mac-help/mchle41a6ccd/mac)与 [macOS 定时任务行为](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/ScheduledJobs.html)。

流程启动后会防止系统自动休眠，这不能解决触发前已经睡眠的问题。游戏也应事先完成更新和登录，国际服、日服尤其需要确认当前已登录账号。

## 安排多个方案

例如：

| 方案 | 星期 | 时间 |
| --- | --- | --- |
| 轻量日常 | 每天 | 09:00 |
| 完整日常 | 每天 | 21:00 |

不同方案的星期与时间完全相同时，AutoMAA 会阻止启用。即使开始时间不同，也要根据实际耗时留出间隔：一个流程尚未结束时，另一个无法同时运行，**不会自动排队等待**。

两个方案都可开启“每周优先剿灭”，并设为周一开始。早晨未满，晚间继续补；任一方案确认本周已满后，其他方案跳过剿灭。无需为了某天剿灭复制一整份日常方案。定时按电脑时间触发，每周剿灭按各服游戏日判断；设置较晚的开始日会减少本周补打机会，见[理智作战](../tasks/fight)。

## 查看后台结果与通知

定时任务使用当前配置与当天断点，保留无需作战和待确认结果；待确认的作战不会自动重跑。结果写入“活动记录”。运行期间打开 AutoMAA，可看到当前阶段和进度。

如需提醒，在“全局设置 → 重要通知”开启权限，并用“测试后台通知”确认可送达。通知包括：

- 公招发现尚未确认处理的高星、特殊或保留标签；
- 客户端需要更新、登录或其他人工处理；
- 流程因安全问题中止，或有步骤最终失败。

公招提醒在该次公招任务结束后发送，其余问题在流程结束时汇总。公招成功且明确报告已招募或已刷新的结果只记入普通活动记录；普通完成与主动停止不会通知。锁屏预览只显示结果概括，完整信息在活动记录中；专注模式与系统通知设置可能延后横幅。

## 更新或移动 App 后

更新 AutoMAA 后先打开一次新版本，让已启用的定时任务自动刷新；已有流程运行时会等待其结束。不要删除或移动定时任务正在使用的 App。

游戏更新后，先暂停相关方案的定时，手动完成游戏准备并跑通一次，再恢复，见[游戏更新与人工处理](../troubleshooting/game-update)。自动 MAA 维护与定时的避让规则见[更新应用与 MAA](./updates#自动更新-maa)。

未按时执行时，按[定时问题排查](../troubleshooting/common#定时任务没有执行)检查活动和 Runner 日志。
