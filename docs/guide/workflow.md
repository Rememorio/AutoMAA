# 执行流程与续跑

**客户端与账号**决定在哪里运行、如何切换；**自动化方案**决定执行对象、任务顺序、参数和时间。同一批账号只配置一次，可以参与不同方案。

## 一次运行怎样执行

```text
检查方案与 MAA 环境
  ↓
启动客户端 A → 账号 1 → 方案中的任务
             → 账号 2 → 方案中的任务
  ↓
关闭客户端 A → 确认 MaaTools 连接释放
  ↓
启动客户端 B → 目标账号 → 方案中的任务
  ↓
关闭客户端 B → 确认连接释放 → 记录结果
```

客户端、账号和任务分别遵循各自的排序。每个客户端使用独立的 MAA 配置；同一时间只运行一个 AutoMAA 工作流。

运行前会统一检查本轮仍有待执行任务的客户端与连接端口。目标客户端已经打开（即使尚未开放 MaaTools 端口）、端口被其他客户端或未知程序占用，或无法确认检测结果时，停止整轮，不接管、切号或关闭外部游戏。请先结束其他 MAA 任务并手动关闭相关客户端，再运行方案。检查在运行前识别数据更新和新轮断点保存之前完成；检查失败保留原轮记录。

这一规则适用于所有服务器，与客户端排列顺序无关。例如国服与日服共用端口时，无论哪一个由独立 MAA 使用、方案先跑哪一个，都会停止整轮。仅打开但空闲的游戏也不会自动接管。全部任务已处理、无需启动游戏时，不检查外部客户端的占用。

## 开启新一轮

同一方案可以一天执行多次。在总览或方案页点击播放，会开启新一轮；每次定时触发也开启新一轮。例如 05:00 手动完成“完整日常”，20:00 的定时仍会重新执行这份方案。

每轮使用方案中当前启用的账号、任务和参数，作战次数、理智药和源石额度每轮重新计算。完成后显示“本轮已完成”及电脑当天已运行的轮数，方案页仍可开始下一轮。开启新轮会归档上一轮，上一轮的部分完成结果保留在运行记录中。

## 继续未完成的任务

断点按方案、当前轮、客户端、账号和任务隔离。只有成功的任务保存成功断点，续跑会跳过本轮已处理任务及已完成的作战阶段。过了电脑零点，只要服务器尚未刷新，当前轮仍可继续；已刷新的服务器结束旧轮续跑，需要开启新轮。以北京时间为例，日服 03:00 刷新，简中服 04:00 刷新。已完成的客户端或账号会跳过启动与切换。

在侧栏选择方案，打开右侧的“运行概况”。“需要处理”按账号列出仍可继续的任务和需要核实的作战。有可续跑的任务时，点击“继续本轮”只补该轮的剩余部分。

理智不足等有明确原因的“无需作战”单独保存，本轮续跑时跳过，新轮会重新检查理智。失败、超时、取消都保留实际结果。未确认的作战会跨新轮和游戏日保留，自动运行会跳过该项并继续其他可执行任务。请先检查游戏，再在“运行概况”的对应账号下核实。总览上只有一项作战需要核实时，点击该事项即可就地打开核实窗口。

如果已核实常规作战并决定跳过今天的重试，在核实窗口选择“今天不再重试常规作战”，点击“确认不再重试”。这项决定只涉及当前方案、当前账号在该游戏日的常规阶段。原始未确认结果仍保留，人工处理在本轮单独计数。核实操作不会生成一次新的运行记录。处理完最后一项后，“需要处理”自动收起，方案可以开启新轮。

例如客户端因网络问题未能登录，恢复网络后点击“继续本轮”，即可补跑剩余任务。其他已成功账号保留原有记录。AutoMAA 不切换 VPN 或更改系统网络设置。

不同方案与不同轮次的完成记录彼此独立。早晨完成某方案的常规作战后，晚间同一方案的新轮仍会执行常规作战。每周剿灭状态按账号共享：两个方案都开启时，早晨未满可以晚间补打，任一方案确认本周奖励已满后其他方案跳过剿灭。未开启该策略的方案不参与补打。游戏内状态会延续，剿灭与常规作战之间的切换见[关卡策略](../tasks/fight#关卡策略)。

本轮任务均已处理、但仍有账号的每周剿灭未满时，结束提示会明确显示待补打账号数。理智不足属于本轮正常结束，不表示本周奖励已经打满。历史摘要保留当次状态，当前是否仍需补打可在所属方案的“运行概况”查看。

## 失败会影响哪些任务

| 情况 | 处理方式 |
| --- | --- |
| 非作战任务失败 | 按方案设置重试，随后停止当前账号或继续后续任务 |
| 理智作战失败 | 本次不自动重跑；后续任务遵循方案设置，可手动继续未完成 |
| 常规作战次数已核实，但部分掉落未识别 | 保存作战断点，继续后续任务；在运行记录中查看缺少掉落明细的次数 |
| 剿灭入口失败且明确尚未开战 | 跳过本次剿灭，继续常规作战与其他日常；周进度待核实 |
| 新发生的作战结果未确认 | 关闭当前客户端并保留结果；后续运行可跳过该作战、继续其他任务，重新尝试作战需明确操作 |
| 找不到账号匹配片段 | 跳过该账号，继续同客户端其他账号 |
| 游戏维护、强制更新或登录确认 | 关闭并跳过该客户端，提示手动处理 |
| 账号准备仍在游戏内资源更新步骤 | 延长本次准备的总等待上限至 10 分钟，仍未就绪则关闭并跳过该客户端，保留未完成任务 |
| 账号准备失败并报告截图连接异常、游戏离线，或未识别到人工处理原因的账号准备超时 | 可使用当前账号的一次恢复机会，安全重启客户端并重试 |
| 非作战任务超时 | 还有单步重试次数和账号恢复机会时，可安全重启后重试。设为 0 次时直接按失败策略处理 |
| 切号时完整回调确认进入设置页后，返回账号选择页失败 | 使用当前账号的一次恢复机会重启客户端，再准备同一账号；仍失败则保留未完成任务并提示手动处理 |
| 目标客户端已打开、相关端口被占用，或检测失败 | 在操作游戏前停止整轮，提示手动关闭相关客户端后重试 |
| 本轮启动的进程被替换，或端口归属改变、无法确认 | 停止流程，不向其他实例发送操作或退出请求 |
| 客户端无法关闭，或关闭后连接未释放 | 停止流程，不启动下一客户端 |

每个账号在一次流程中最多触发一次客户端自动重启，设置页切号导航失败、连接异常及非作战任务超时共用这次机会。前一个账号恢复后，后续账号仍保留自己的恢复机会；同一账号重启后仍无法恢复，则跳过该客户端剩余任务，不会在未知界面反复重启。恢复与收尾只操作本轮启动且身份仍可确认的客户端；重启前仍须确认原实例退出和连接释放，并重新检查占用。

普通账号准备的上限为 2 分钟。到达上限时，本次完整核心回调若仍确认停在游戏内资源更新步骤，会继续等待同一个命令，将单次准备的总上限延长到 10 分钟。延长等待时，侧栏与运行日志显示“正在等待游戏资源更新”。重复下载回调不会再次延长时限。达到总上限后，提示手动确认游戏已进入主界面，再在方案的“运行概况”继续本轮。延长等待后最终日志不完整时，同样交由人工确认。

已经离开更新步骤、回调不完整或仅在诊断文字中提到更新，均沿用普通准备时限。明确的强制更新、维护或登录确认提示优先进入人工处理。用户取消与连续截图失败仍可提前结束延长等待，实际报告游戏离线时按连接恢复规则处理。

AutoMAA 在连接和关闭前核对本轮启动的进程身份与监听端口归属。这不能阻止其他软件在运行途中主动连接同一个游戏；运行期间请勿让另一份 MAA 同时操作该客户端。

客户端退出瞬间可能出现端口状态变化。若检测过程中监听进程消失，AutoMAA 会再次确认端口是否已释放；只有当前进程已退出且端口确认释放后才继续。端口仍开放但归属不明、出现其他监听进程或检测失败时，仍会停止整轮。

账号准备期间，客户端启动和重启统一由 AutoMAA 管理。MAA 只负责切换账号与进入主界面；检测到游戏离线后交回 AutoMAA 处理，避免 MAA 在关闭原生客户端后无法重新启动，却继续尝试截图。

单步失败重试可设为 0–3 次。每次派发任务按照实际使用的参数计算时限。推荐公招执行 4 次，限时 7 分钟。推荐基建执行完整换班，限时 30 分钟。切回推荐模式后，保留的自定义设置在重新启用时生效。作战按单次派发计时，超时归入结果未确认。进度表示流程已处理到的位置，不等于所有任务成功。历史中的“部分完成”描述该次运行。后续核实与续跑的最新状态显示在方案的“运行概况”。

## 安全停止

手动或后台定时运行中，可在今日总览的“当前运行”卡片点击“安全停止”，也可使用方案或运行记录页顶栏的停止按钮，或按 `Command-.`。总览顶栏不显示停止按钮；点击后卡片内按钮保留并禁用，等待清理完成。AutoMAA 会终止当前 MAA 命令、关闭本轮启动且身份仍可确认的客户端并释放连接；尚未启动游戏时不会关闭外部客户端。归属无法确认时停止清理并提示手动检查。等待清理完成后再进行其他操作，已经成功的步骤仍保留本轮断点，可从方案的“运行概况”继续。

## 退出 AutoMAA

关闭窗口后应用仍保留。退出应用时会先保存当前配置；保存失败会保留应用并显示重试入口。运行或更新期间退出，需要确认安全停止或取消更新，清理完成后才退出。

无法安全停止、清理失败或等待超过 2 分钟时，会取消本次退出并保留提示。先在运行记录中检查状态，等待清理完成后再重试。

## 查看运行记录

方案的任务行在运行期间即时更新。正在执行的任务显示转圈，所有目标账号完成该项后显示绿勾，已确定失败显示红叉。

“运行记录”的中列在运行时显示当前流程，已结束的运行按开始日期排列。选择一行可在右侧查看结果或完整日志。刷新或收到新事件时会保留正在阅读的历史记录。独立 MAA 更新的日志保存在“设置 → MAA 环境 → 维护记录”。

方案页右侧的“运行概况”在本方案运行时显示实时日志。停止后，有剩余任务或需核实的作战时，直接显示可用操作，并提供带日期的最近记录入口。处理完成后显示本轮摘要和最近结果。点击任务可回到“任务设置”。

同一方案、同一轮次在短时间内连续因相同占用而无法启动时，历史将这些尝试折叠为一组。展开可查看每一次的时间和原始记录，实际开始执行的运行单独列出。历史行显示时间、方案、结果和摘要，与总览的最近运行使用相同状态样式：已完成显示绿色小勾，部分完成、未完成、待核实及剿灭待补打显示橙色图标与状态，失败显示红色，已停止与人工处理保持中性色。选中历史后，详情列顶栏的清单图标显示“运行结果”，日志列表图标显示“完整日志”，悬停可查看名称。后台正在运行时，安全停止位于这组切换按钮左侧。

结果先列出异常与对应账号，再显示本次有结算证据的作战关卡、次数和已识别掉落。以前轮次留下的待核实作战只提示本次跳过。其他已处理任务先显示摘要，可展开查看明细。完整日志使用时间、信息两列和隔行底色，普通进度与任务完成正文使用系统黑／白色，连接成功、资源校验与 MAA 维护结果使用浅色靛蓝、深色薄荷绿，提醒与错误分别使用橙色、红色，并可选择“只看警告与错误”。仅整轮最终结论附加对应的结果符号，普通日志行不逐条重复打勾。长诊断按需展开，文字可选择、复制。自动重试、原目标无法进入与兜底结果均保留；缺少结束事件时显示“未记录结束”并使用橙色提示。

搜索框右侧的筛选图标提供“全部／提醒／失败”，当前条件显示在列表底部。搜索与筛选仅影响历史，当前运行保持可见。“提醒”包含警告、错误、未完成与当次待补剿灭；“失败”依据当次最终结果或失败步骤，保留整次运行上下文。通过侧栏返回记录时会保留条件。从总览点击“全部记录”会同时清除历史搜索和筛选，退出应用后也会清空。搜索框清除按钮只清除关键词，“清除筛选”恢复全部历史。

方案运行前的资源更新保留在该次完整日志中。遇到影响运行的更新问题，结果页会显示提醒。实时日志提供“跟随最新”开关，关闭后可自由阅读前面的事件。

“记录操作”菜单可以打开诊断日志目录或清除方案运行历史。独立维护历史可在 MAA 环境中单独清除。两种清除操作都保留诊断文件、当前轮断点和每周剿灭状态。失败或结果未确认时，记录会尽可能显示目标关卡与失败阶段；目标不代表实际开战，缺少证据时会标明阶段或原因未确认。
