# 理解执行流程

AutoMAA 的核心是“客户端 → 账号 → 任务”三层顺序。所有层级都由用户动态配置，没有写死的服务器或账号。

## 严格串行

一个典型流程如下：

```text
准备 MAA 配置
  ↓
启动客户端 A → 账号 1 → 任务 1、2、3
             → 账号 2 → 任务 1、2、3
  ↓
关闭客户端 A → 确认 MaaTools 端口释放
  ↓
启动客户端 B → 账号 1 → 任务 1、2、3
  ↓
关闭客户端 B → 确认端口释放 → 完成
```

AutoMAA 不会同时连接两个客户端，也不会在 1717 仍被旧客户端占用时贸然连接下一项。

## 每个步骤独立调用 MAA

AutoMAA 为每个客户端生成独立 Profile，为每个账号任务生成独立 Task 文件。这样可以：

- 隔离不同服务器的资源；
- 精确记录哪个账号的哪个任务成功；
- 单步骤失败后重试或继续，而不必重跑整条链路；
- 在日志中清楚区分客户端、账号和任务。

这些文件由 AutoMAA 管理，不建议手工修改。

## 当日断点

任务成功后会写入当天完成记录。同一天再次运行时，AutoMAA 会自动跳过已经成功的步骤。

以下情况不会写入成功断点：

- MAA 返回失败；
- 命令超时；
- 用户安全停止；
- 游戏需要人工处理；
- 客户端或账号被跳过。

如需当天重跑所有任务，可在“全局设置”中选择“重置今日完成记录”。重置只清理 AutoMAA 的完成记录，不会恢复游戏内已经消耗的理智或道具。

## 错误影响范围

| 情况 | 默认处理 |
| --- | --- |
| 找不到账号匹配片段 | 跳过当前账号，继续同客户端其他账号 |
| 游戏维护、强制更新或数据下载 | 关闭并跳过当前客户端 |
| 单个日常任务失败 | 按配置重试；随后停止账号或继续后续步骤 |
| 端口被未知进程占用 | 停止流程，避免连接错误实例 |
| 客户端关闭后端口不释放 | 停止流程，不启动下一客户端 |
| 用户点击安全停止 | 取消当前命令、关闭客户端并释放连接 |

安全问题优先于“尽量跑完”。如果 AutoMAA 无法证明下一步连接的是正确客户端，它会停止并要求人工确认。
