# 理解执行流程

AutoMAA 分成两类配置：

- **客户端与账号**描述“谁、在哪里、如何切换”；
- **自动化方案**描述“对哪些账号、按什么顺序、用什么参数、在什么时间执行”。

同一批账号只配置一次，可以同时参与轻量收菜、完整换班、周末或临时方案。

## 严格串行

一个方案的典型流程如下：

```text
准备指定方案的 MAA 配置
  ↓
启动客户端 A → 目标账号 1 → 方案步骤 1、2、3
             → 目标账号 2 → 方案步骤 1、2、3
  ↓
关闭客户端 A → 确认 MaaTools 端口释放
  ↓
启动客户端 B → 目标账号 1 → 方案步骤 1、2、3
  ↓
关闭客户端 B → 确认端口释放 → 完成
```

AutoMAA 不会同时连接两个客户端，也不会在当前配置的 MaaTools 地址仍被旧客户端占用时贸然连接下一项。

## 每个步骤独立调用 MAA

AutoMAA 为每个客户端生成独立 Profile，并按“方案 + 客户端 + 账号 + 任务”生成独立 Task 文件。这样可以：

- 隔离不同服务器的资源；
- 让同一账号在不同方案中使用不同任务参数；
- 精确记录哪个方案、账号和任务成功；
- 单步骤失败后重试或继续，而不必重跑整条链路。

这些文件由 AutoMAA 管理，不建议手工修改。

选择“上次成功的常规关卡”时，任务文件会按客户端和账号写入各自记住的关卡。任何目标账号缺少记录时，对应方案会在运行前检查阶段停止；AutoMAA 不会生成一个退回 MAA“当前/上次”的任务来掩盖缺失状态。

自动重试会在活动记录中保留失败原因，并在恢复后明确标记“重试后已就绪”或“重试后已完成”。已经自动恢复的过程不会计入“需留意”；只有重试全部耗尽、任务最终失败或需要人工确认时才会显示警告。

不同任务使用与工作量匹配的超时预算：公开招募会考虑配置的招募次数，基建会区分收菜、完整换班和自定义排班，理智作战则保留长任务预算。达到上限不等于任务成功，也不会写入当天断点。

若 MAA 明确报告游戏连接已经离线，或账号准备、某个日常任务执行超时，AutoMAA 会安全关闭当前客户端、确认 MaaTools 端口释放并重启一次，然后重新准备账号；任务超时时还会重试当前任务。游戏离线、准备超时和任务超时共用每客户端每次流程一次的受控恢复预算。恢复后仍超时会跳过该客户端的其余步骤并要求人工确认，不会让后续任务继续在未知界面逐个等待。

累计进度表示本次流程已经处理到的位置，不等同于全部任务成功。流程正常收尾但仍有步骤失败或因异常未执行时，活动记录会标记为“部分完成，需处理”，并分别列出完成、失败与未执行步骤数；当天断点中已经成功的步骤仍计为完成。

## 当日断点

任务成功后会写入当前方案当天的完成记录。同一方案在同一天再次运行时，会跳过已经成功的步骤；不同方案即使包含同名任务，也不会互相跳过。

以下情况不会写入成功断点：

- MAA 返回失败；
- 命令超时；
- 用户安全停止；
- 游戏需要人工处理；
- 客户端或账号被跳过。

如需当天重跑所有方案，可在“全局设置”中选择“重置今日完成记录”。重置只清理 AutoMAA 的完成记录，不会恢复游戏内已经消耗的理智或道具。

## 错误影响范围

| 情况 | 默认处理 |
| --- | --- |
| 找不到账号匹配片段 | 跳过当前账号，继续同客户端其他账号 |
| 游戏维护、强制更新或数据下载 | 关闭并跳过当前客户端 |
| 单个日常任务失败 | 按当前方案配置重试；随后停止账号或继续后续步骤 |
| 账号准备或单个日常任务超时 | 安全重启当前客户端一次并重试；再次超时则关闭并跳过该客户端其余步骤 |
| 其他已配置客户端占用同一端口 | 指出冲突客户端并停止流程，不自动关闭用户手动打开的游戏 |
| 端口被未知进程占用 | 停止流程，避免连接错误实例 |
| 客户端关闭后端口不释放 | 停止流程，不启动下一客户端 |
| 用户点击安全停止 | 取消当前命令、关闭客户端并释放连接 |

安全问题优先于“尽量跑完”。如果 AutoMAA 无法证明下一步连接的是正确客户端，它会停止并要求人工确认。
