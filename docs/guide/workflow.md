# 执行流程与续跑

**客户端与账号**决定在哪里运行、如何切换；**自动化方案**决定执行对象、任务顺序、参数和时间。同一批账号只配置一次，可以参与不同方案。

## 一次运行怎样执行

```text
检查方案与 MAA 环境
  ↓
启动客户端 A → 账号 1 → 方案中的任务
             → 账号 2 → 方案中的任务
  ↓
关闭客户端 A → 确认 MaaTools 连接释放
  ↓
启动客户端 B → 目标账号 → 方案中的任务
  ↓
关闭客户端 B → 确认连接释放 → 记录结果
```

客户端、账号和任务分别遵循各自的排序。每个客户端使用独立的 MAA 配置；同一时间只运行一个 AutoMAA 工作流。

## 当天再次运行

成功步骤按“日期 + 方案 + 客户端 + 账号 + 任务”记录。当天运行过但仍有可执行任务时，运行入口显示“继续未完成”；点击后只补跑未完成步骤，已经完成的客户端或账号不必再次启动或切换。活动记录顶部的“当前待办”提供方案选择、当前进度与同一运行入口。

今日尚未运行时，活动记录只显示状态与下次定时时间，不展开尚未开始的任务；跨日刷新也不会生成一长列待办。运行开始后，总览与活动记录按客户端、账号折叠展示剩余任务或作战阶段，展开后可查看已知的停止原因。只剩每周剿灭时会说明周奖励仍待补打；只剩常规作战时不会把已处理的剿灭列入续跑范围。这些待办由当前断点推导，清除历史或筛选记录不会改变执行范围。

理智不足等有明确原因的“无需作战”单独保存，当天续跑会跳过。失败、超时、取消不会记为成功。有待确认作战及其他可执行任务时，按钮显示“继续其他任务”，明确保留待确认作战；没有其他可执行任务时显示“结果待确认”。检查游戏后，可在顶部“需要处理”中独立确认本周剿灭已满，或重新尝试作战。全部处理完毕后显示“今日已完成”。

例如客户端因网络问题未能登录，修复网络后点击“继续未完成”，即可补跑它的任务，其他已成功账号保持原有记录。AutoMAA 不切换 VPN 或更改系统网络设置。

不同方案的每日完成记录彼此独立。例如早晨的轻量方案完成过常规作战，晚间的完整方案仍会执行自己的常规作战。每周剿灭状态按账号共享：两个方案都开启时，早晨未满可以晚间补打，任一方案确认本周奖励已满后其他方案跳过剿灭。未开启该策略的方案不参与补打。游戏内状态会延续，剿灭与常规作战之间的切换见[关卡策略](../tasks/fight#关卡策略)。

本轮任务均已处理、但仍有账号的每周剿灭未满时，结束提示会明确显示待补打账号数。理智不足属于本轮正常结束，不表示本周奖励已经打满。历史摘要保留当次状态，当前是否仍需补打以“当前待办”为准。

需要当天重新执行所有方案时，可在“全局设置”选择“重置今日完成记录…”。它保留配置和活动记录，但不会恢复游戏中已消耗的理智或道具，请确认后再重跑。

## 失败会影响哪些任务

| 情况 | 处理方式 |
| --- | --- |
| 非作战任务失败 | 按方案设置重试，随后停止当前账号或继续后续任务 |
| 理智作战失败 | 本次不自动重跑；后续任务遵循方案设置，可手动继续未完成 |
| 剿灭入口失败且明确尚未开战 | 跳过本次剿灭，继续常规作战与其他日常；周进度待核实 |
| 新发生的作战结果未确认 | 关闭当前客户端并保留结果；后续运行可跳过该作战、继续其他任务，重新尝试作战需明确操作 |
| 找不到账号匹配片段 | 跳过该账号，继续同客户端其他账号 |
| 游戏维护、强制更新、登录确认或数据下载 | 关闭并跳过该客户端，提示手动处理 |
| 账号准备失败并报告截图连接异常、游戏离线，或账号准备、非作战任务超时 | 安全重启当前客户端一次并重试；仍无法恢复时跳过该客户端 |
| 其他客户端或未知进程占用连接端口 | 停止流程，提示确认占用者 |
| 客户端无法关闭，或关闭后连接未释放 | 停止流程，不启动下一客户端 |

每个账号在一次流程中最多触发一次客户端自动重启，账号准备与非作战任务共用这次机会。前一个账号恢复后，后续账号仍保留自己的恢复机会；同一账号重启后仍有连接异常或超时，则跳过该客户端剩余任务，不会在未知界面反复重启。重启前仍须确认客户端关闭和连接释放。AutoMAA 不会为解除端口冲突而自动关闭用户手动打开的其他游戏。

任务超时预算会随任务类型与参数调整；达到上限不会记为成功，作战超时归入结果未确认。进度表示流程已处理到的位置，不等于所有任务成功。历史显示“部分完成”时描述的是那次运行；后续处理后的最新状态以“当前待办”为准。

## 安全停止

运行中点击“安全停止”或按 `Command-.`。AutoMAA 会终止当前 MAA 命令、关闭当前客户端并释放连接；等待清理完成后再进行其他操作。已经成功的步骤仍保留当天完成记录。

## 查看活动记录

“活动记录”首先显示当前需要处理的事项、运行状态和今日进度，再展示历史。顶部“需要处理”汇总各方案的待确认作战，按方案折叠；查看另一个方案、搜索或清除历史，都不会隐藏这些处理入口。

历史按运行开始日期分组，每次运行显示时间、方案、结果和摘要，默认折叠。展开后先看账号任务结果，再按需展开“提醒与错误”或“完整过程”；完整过程可临时选择“只看警告与错误”。自动重试、原目标无法进入与兜底结果均保留，历史只描述当次情况，不表示现在仍需处理。缺少结束事件时显示“未记录结束”，不把历史进度当作仍在运行。

记录区使用“全部 / 提醒 / 失败”筛选整次运行。“提醒”包含警告、错误、未完成事项和当次待补打的剿灭；“失败”包含最终失败或有失败步骤的运行，已恢复的重试错误归入提醒。搜索可匹配方案、客户端、账号、任务、消息与详情，命中后仍保留该次运行的完整上下文。

搜索和筛选栏在记录区吸顶，窄窗口自动分行；切换页面后保留条件，退出应用后清空。搜索框内的清除按钮只清除关键词，“清除筛选”恢复全部历史。当前运行保留独立的实时记录与“跟随最新”开关，不受历史搜索和筛选影响。

右侧“记录操作”菜单提供诊断日志与清除历史入口。清除历史不改变日常断点、每周剿灭状态或当前处理入口。展开详情可阅读和复制长内容，作战结果保留实际关卡、次数和掉落。
