# 执行流程与续跑

**客户端与账号**决定在哪里运行、如何切换；**自动化方案**决定执行对象、任务顺序、参数和时间。同一批账号只配置一次，可以参与不同方案。

## 一次运行怎样执行

```text
检查方案与 MAA 环境
  ↓
启动客户端 A → 账号 1 → 方案中的任务
             → 账号 2 → 方案中的任务
  ↓
关闭客户端 A → 确认 MaaTools 连接释放
  ↓
启动客户端 B → 目标账号 → 方案中的任务
  ↓
关闭客户端 B → 确认连接释放 → 记录结果
```

客户端、账号和任务分别遵循各自的排序。每个客户端使用独立的 MAA 配置；同一时间只运行一个 AutoMAA 工作流。

## 当天再次运行

成功步骤按“日期 + 方案 + 账号 + 任务”记录。同一方案当天再次运行时，会跳过已经成功的步骤；完成过的客户端或账号也不必再次启动或切换。失败、超时、取消和被跳过的步骤不会记为成功。

不同方案的完成记录彼此独立。例如早晨的轻量方案完成过理智作战，晚间的完整方案仍会执行自己的理智作战。游戏内状态则会延续，剿灭与常规作战之间的切换见[关卡策略](../tasks/fight#关卡策略)。

需要当天重新执行所有方案时，可在“全局设置”选择“重置今日完成记录…”。它保留配置和活动记录，但不会恢复游戏中已消耗的理智或道具，请确认后再重跑。

## 失败会影响哪些任务

| 情况 | 处理方式 |
| --- | --- |
| 单个任务失败 | 按方案设置重试，随后停止当前账号或继续后续任务 |
| 找不到账号匹配片段 | 跳过该账号，继续同客户端其他账号 |
| 游戏维护、强制更新、登录确认或数据下载 | 关闭并跳过该客户端，提示手动处理 |
| 游戏离线、账号准备或日常任务超时 | 安全重启当前客户端一次并重试；仍无法恢复时跳过该客户端 |
| 其他客户端或未知进程占用连接端口 | 停止流程，提示确认占用者 |
| 客户端无法关闭，或关闭后连接未释放 | 停止流程，不启动下一客户端 |

每个客户端在一次流程中最多自动重启恢复一次，不会在未知界面反复重启。AutoMAA 不会为解除端口冲突而自动关闭用户手动打开的其他游戏。

任务超时预算会随任务类型与参数调整；达到上限仍属于失败。进度表示流程已处理到的位置，不等于所有任务成功。正常收尾但仍有失败或未执行步骤时，结果会显示“部分完成，需处理”。

## 安全停止

运行中点击“安全停止”或按 `Command-.`。AutoMAA 会终止当前 MAA 命令、关闭当前客户端并释放连接；等待清理完成后再进行其他操作。已经成功的步骤仍保留当天完成记录。

## 查看活动记录

“活动记录”按每次运行分组，显示方案、账号、任务和结果。自动重试的过程会保留，成功恢复后会明确标记；“需留意”只筛选最终警告或错误，不会把已恢复的重试当成未解决的问题。

可以按方案、客户端、账号、任务或消息搜索。搜索和筛选在切换页面后保留；选择“清除筛选”恢复全部记录。展开“详情”可阅读和复制长内容，作战汇总可查看实际关卡、次数和掉落。

后台定时任务的进度也会同步到这里。需要提交问题时，从“更多”打开诊断日志，并按[问题报告说明](../troubleshooting/common#怎样提交有效的问题报告)提供相关片段。
