# 理智作战

理智作战调用 MAA 的 `Fight` 任务。初次使用建议保持不使用理智药和源石，并先在有人值守时验证一次。

## 关卡策略

| 策略 | 行为 |
| --- | --- |
| 游戏当前/上次 | 不指定关卡，由 MAA 使用游戏当前或上次作战 |
| 跟随游戏，剿灭后恢复 | 平时跟随游戏当前/上次；AutoMAA 执行剿灭后，下次按账号恢复一次备用常规关卡 |
| 固定关卡 | 选择预设或直接填写 MAA 支持的关卡名 |

“游戏当前/上次”最适合活动期间手动准备好关卡后继续刷取，但它会受到游戏最近作战记录影响：其他方案执行剿灭后，下一次也可能继续进入剿灭。固定关卡适合目标长期不变的日常。

“跟随游戏，剿灭后恢复”把备用关卡只用于保护剿灭后的下一次作战，而不是长期强制指定旧关卡。正常情况下它向 MAA 传入空关卡，因此用户在游戏里从活动关切到 `1-7` 后，下一次会直接跟随 `1-7`；maa-cli 明确报告实际完成次数大于零后，AutoMAA 再把该关卡记为新的备用关卡。

AutoMAA 成功执行固定剿灭，或任务摘要明确确认进入剿灭时，会按客户端和账号标记“待恢复”。采用此策略的下一次理智作战会明确返回备用常规关卡一次；确认常规作战成功后自动清除标记，之后重新跟随游戏。剿灭不会覆盖备用关卡，零次常规作战、失败、超时和取消也不会学习或清除恢复状态。

若剿灭前还没有备用关卡，运行前检查只会在确实需要恢复时阻止理智作战。可以在方案的账号恢复状态中设置关卡；若已在游戏里手动切回常规关卡，也可以选择“游戏已手动切回，继续跟随”，让下一次直接采用游戏当前/上次。

固定关卡仍包含 `1-7`、`CE-6`、`LS-6`、`AP-5`、`CA-5`、`SK-5`、当期或固定剿灭、`OF-1`、`OF-F3` 与手动输入。资源关卡是否回落、剿灭扫荡卡和代理次数等实际行为继续由当前 MaaCore 决定。

作战成功后，AutoMAA 会从 maa-cli 的任务摘要中提取实际关卡和完成次数，并在活动记录详情中显示本次总掉落。若当前 maa-cli 未返回对应摘要，任务仍会正常记为完成，但不会补充作战汇总、学习常规关卡或清除待恢复状态；固定剿灭仍会保守标记待恢复，因为它已经可能改变游戏的最近作战。

## 消耗与次数

- **理智药**：允许使用普通理智药的数量。
- **临期理智药天数**：使用指定天数内到期的理智药，例如 `2` 表示两天内。AutoMAA 使用当前 MAA 参数 `medicine_expire_days`，不是已弃用的“药品数量”参数。
- **源石**：允许使用源石恢复理智。除非完全理解后果，建议保持关闭。
- **次数**：限制执行次数；留空时由理智和 MAA 行为决定。
- **连战**：“保持当前”不写入参数，`-1` 关闭切换，`AUTO` 自动选择当前可用最大次数，也可指定 1–10。可用上限仍以当前游戏和 MAA 适配为准。
- **博朗台模式**：使用 MAA 对应的节约理智策略。

::: danger 源石消耗不可恢复
自动使用源石会产生真实账号资源消耗。首次配置、游戏大版本更新或 MAA 尚未适配新作战界面时，请保持关闭。
:::

## 上游适配期间

如果游戏刚修改作战、连战或结算界面，应以 MAA 的当前适配状态为准。AutoMAA 只负责传递参数，不会绕过 MaaCore 的兼容性限制。必要时暂时关闭理智作战，先运行公招和基建等已确认任务。
