# 理智作战

为方案选择关卡和允许的资源消耗。初次运行先关闭理智药、源石等额外消耗，确认任务行为后再调整。

## 关卡策略

| 策略 | 适合什么情况 |
| --- | --- |
| 游戏当前/上次 | 已在游戏里选好要刷的关卡，希望继续跟随 |
| 跟随游戏，剿灭后恢复 | 平时跟随游戏，AutoMAA 执行剿灭后恢复一次常规关卡 |
| 固定关卡 | 每次都刷同一关卡或固定剿灭 |

游戏的最近作战会影响“当前/上次”：另一个方案执行过剿灭后，日常也可能继续进入剿灭。需要避免这种情况时，选择恢复策略或固定关卡。

固定关卡可选资源关、剿灭、OF 关卡，也可输入 MAA 支持的关卡名。是否开放、能否使用扫荡卡等行为仍由游戏与所安装的 MaaCore 决定。

## 剿灭后的关卡恢复

“跟随游戏，剿灭后恢复”平时仍使用游戏当前或上次关卡。成功完成常规作战并取得有效结算后，AutoMAA 会为该账号记录常规关卡，例如 `1-7`。

AutoMAA 根据结算流程中的作战类型识别剿灭，各服共用同一规则，不使用地图的中文、日文或其他语言名称猜测。确认完成剿灭后，会标记该账号需要恢复。采用恢复策略的下一次作战会返回记录的常规关卡；成功后清除标记，之后继续跟随游戏。

需要恢复却没有记录关卡时，运行检查会提示处理。可以在方案中的账号恢复状态里设置关卡；已经在游戏中手动切回时，选择“游戏已手动切回，继续跟随”。

记录关卡只接受 `1-7`、`CE-6`、`PR-A-1` 等由字母、数字和连字符组成的关卡编号，具体导航能力仍取决于 MAA。地图显示名称和无效识别结果不会保存为记录关卡；即使作战已完成，未确认作战类型或未识别出有效编号时，也不会覆盖原记录。

升级后发现旧关卡记录包含地图名称时，只停用该账号的无效记录并提示设置备用关卡，其他账号的有效记录保留。读取时不改写原文件；首次保存修复后的记录前，会在数据目录保留 `fight-stage-memory.backup-*.json` 备份。

失败、无需作战、结果未确认、超时和取消不会学习关卡或清除恢复状态。仅退出成功或显示作战次数，都不能证明已经结算。

作战次数按已确认的结算累计。结算未识别出连战次数时，使用与这次结算对应的开战倍率；两者都无法确认时显示“至少 N 次”，不会把一批连战当成准确的一局。理智不足和达到指定次数会分别显示结束原因。

## 目标无法进入时使用兜底关卡

自定义参数中的“兜底关卡”默认留空。可填写已解锁的常驻关卡，例如 `1-7`；它属于方案，和账号自动记录的恢复关卡相互独立。

固定关卡、剿灭后恢复和跟随游戏使用相同规则：只有明确观察到选关失败，且没有进入作战流程或发现已有战斗时，才会重新确认同一账号就绪并尝试一次兜底。关卡可能尚未开放、已关闭、未解锁或暂不支持导航，因此提示“无法进入目标关卡”，不会把识别失败直接判定为今日未开放。各服依据实际 MAA 回调处理，不用本机星期推测开放日。

兜底使用原方案的理智药、源石、次数和连战设置；原目标没有开战，不会重新获得一份已消耗的预算。原目标与兜底相同、兜底也失败、理智不足、超时、掉线或战果不明时，都不会继续换关。剿灭入口无法确认仍需人工处理，不能由常规兜底代替。

临时兜底的实际关卡和结果会显示在活动记录中，但不会更新账号记录的常规关卡或清除原恢复目标。恢复 `AP-5` 失败后临时刷 `1-7`，下次仍会尝试恢复 `AP-5`；固定关卡也继续使用原设置。若原策略为跟随游戏且原关卡未知，则不猜测原目标，下次继续跟随游戏；希望始终恢复到明确关卡时，请设置固定关卡或恢复目标。

兜底结果正常完成后，该次作战可以完成；兜底中断时保留已选目标并等待确认，重跑不会顺带重复已完成的剿灭。

明确选关失败且尚未开战时，可以先修改方案的固定关卡、兜底关卡或账号恢复目标，再“继续未完成”；本次会重新选择目标，已完成的剿灭保留。若已经开战或结果未确认，则保留上次派发的具体目标，处理对话框会显示重跑关卡；修改方案不会悄悄改变这次待确认作战。

## 优先完成本周剿灭

在自定义参数中开启“优先完成本周剿灭”，同一项理智作战会分为两个阶段：先执行当期剿灭，再刷常规关卡。默认关闭；原有固定剿灭方案仍只执行剿灭。

后续关卡会在剿灭开始前确定：固定策略使用指定的常规关卡，其他策略使用该账号最近成功的常规关卡或手动设置的恢复关卡。没有记录时必须先设置；后续关卡不能再次指定剿灭。执行中和当天续跑都保留这次确定的关卡，避免游戏的“上次作战”被剿灭覆盖。旧进度中的后续目标若为无效地图名称，续跑会采用修正后的常规关卡，同时保留已完成的剿灭阶段。

剿灭阶段只使用现有理智，不使用理智药、临期药或源石，也不占用指定的常规作战次数。常规阶段使用方案中的消耗与次数设置；理智不足时仍会尝试常规关卡，因为其消耗可能更低。

每个阶段独立保存结果。剿灭完成、常规作战失败时，续跑只执行常规阶段。如果找不到剿灭入口，AutoMAA **不会据此判断本周已满**，也不会自动进入常规阶段。请检查游戏，在活动记录的“处理作战结果…”中选择重跑；已在游戏中确认本周剿灭完成时，可选择“已确认本周剿灭完成，继续常规”。这项手动确认只影响当前方案、账号和当天的剿灭阶段。

## 消耗与次数

| 设置 | 含义 |
| --- | --- |
| 理智药 | 允许使用的普通理智药数量 |
| 临期理智药天数 | 使用指定天数内到期的理智药，例如 `2` 表示两天内 |
| 源石 | 允许使用源石恢复理智 |
| 次数 | 限制执行次数；留空由理智与 MAA 行为决定 |
| 连战 | 保持游戏当前设置、关闭切换，或选择自动最大次数、指定 1–10 次 |
| 博朗台模式 | 使用 MAA 对应的节约理智策略 |

可用连战上限取决于游戏与 MAA 适配。**源石消耗不可恢复**，只有明确接受相应消耗时才开启。

## 查看作战结果

“活动记录”区分以下结果：

| 结果 | 判定与后续行为 |
| --- | --- |
| 已完成 | 本次 MaaCore 进程提供有效结算，且命令正常结束；保存成功断点 |
| 无需作战 | 明确识别到理智不足或本周剿灭奖励已满；单独保存原因，当天续跑不重复执行 |
| 结果未确认 | 缺少结算、执行中断或剿灭入口无法确认；暂停该客户端剩余任务，需要人工处理 |
| 失败 | 命令明确失败且未观察到已完成的作战；保留失败状态，可通过“继续未完成”重跑 |

实际关卡与完成次数以本次进程的结算回调为依据；maa-cli 摘要仅补充总掉落。摘要次数可能包含刚开始、尚未结算的作战，不能单独作为完成证明。当前 Core 未提供可识别的回调时，会显示结果未确认。

结果未确认时，先检查游戏，再从当天对应记录中选择“处理作战结果… → 重跑本项”。已经完成的阶段保留；未确认的阶段可能已经消耗理智或道具，重跑会再次执行。取消和程序意外退出也保留待确认状态。

游戏刚更新作战或结算界面时，可能需要等待 MAA 适配。可暂时关闭受影响任务，按[游戏更新说明](../troubleshooting/game-update#游戏界面已经变化-maa-尚未适配)处理。
