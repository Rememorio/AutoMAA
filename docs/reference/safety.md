# 安全与隐私边界

AutoMAA 会启动和关闭游戏客户端，并调用 MAA 执行游戏内操作。为了让自动化保持可控，项目遵循以下边界。

## AutoMAA 会做什么

- 保存用户明确输入的客户端、账号片段和任务设置；
- 为不同客户端生成隔离的 MAA Profile；
- 串行启动、切换和关闭客户端；
- 调用本机 `maa-cli`；
- 记录步骤结果与必要错误信息；
- 安装用户主动启用的 LaunchAgent 定时任务。

## AutoMAA 不会做什么

- 保存或填写密码、验证码；
- 绕过登录、用户协议、维护和强制更新；
- 下载或安装游戏包体；
- 在无法确认端口归属时继续连接；
- 将账号、日志或配置上传到 AutoMAA 服务端；
- 静默启动两个客户端并行操作。

AutoMAA 本身没有云端账号系统。GitHub Pages 文档站是静态站点，不接收 AutoMAA 配置或运行数据。

## 日志分享

提交 Issue 前检查并移除：

- 完整手机号和账号匹配片段；
- 本机用户名与私人目录；
- 游戏账号名称；
- 访问令牌、Cookie、代理地址和认证信息；
- 包含私人通知或其他 App 内容的截图区域。

推荐只提供与问题相邻的少量日志，而不是整个数据目录。

## 安装包信任

当前临时签名版本会触发 macOS Gatekeeper 提示。只从官方 Release 下载、核验 SHA-256，并使用系统提供的单 App“仍要打开”流程。详见[下载与安装](../guide/installation)。

项目未来完成 Developer ID 签名与公证后，应以新的官方文档为准。
