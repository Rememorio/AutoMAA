# 游戏更新与人工处理

## 各种更新分别是什么

| 内容 | 用途与更新方式 |
| --- | --- |
| AutoMAA App | 界面、方案编排、定时与安全控制。在“全局设置 → AutoMAA 更新”下载，确认重启后安装 |
| MAA 引擎（MaaCore） | 识别与执行任务的程序。在“全局设置 → MAA 更新”选择“更新 MAA”，使用稳定版 |
| MAA 识别数据 | 界面、关卡和活动的识别规则与图片。包含随引擎发布的基础数据和单独发布的增量数据 |
| maa-cli | 调用和管理 MAA 的命令行工具。通过原安装方式（例如 Homebrew）单独升级 |
| 游戏 App 包体 | 在当前游戏运行环境中手动更新 |
| 游戏内数据下载与解压 | 由游戏客户端完成，用户等待并确认 |

**“更新 MAA”已包含识别数据同步。** “仅更新识别数据”执行较小的热更新，不更换引擎；适合引擎无需升级时同步最新识别规则。方案的“运行前更新识别数据”执行同一流程。基础数据、MaaResource 增量和在线任务数据共同组成 MAA 实际使用的识别数据，不是游戏包体。

开启空闲自动更新后，AutoMAA 每 24 小时最多尝试一次稳定版，并避让运行中的方案和 90 分钟内的定时任务。预发布版尚未进入稳定通道时会保留当前安装，自动维护不会降级或切换 Beta。

## 更新耗时、取消与失败

| 操作 | 上限（含重试） |
| --- | --- |
| 检查 AutoMAA 版本 / MAA 稳定版清单、重新校验已下载的 AutoMAA 更新包 | 每项 30 秒 |
| 仅更新识别数据，含运行前更新 | 3 分钟，包含校验 |
| 完整 MAA 更新 / AutoMAA 下载与校验 | 15 分钟，包含校验 |

自动与手动入口共用这些规则。临时网络错误最多重试一次，重试不会重置计时；如果网络提前断开、服务器拒绝请求或校验不通过，操作会更早结束。上限到达后还需要短暂终止进程和清理临时文件，因此不同错误不一定恰好在同一秒出现。

更新过程中显示当前阶段与已用时间。“取消更新”或 `Command-.` 会停止当前操作，包括 maa-cli 启动的下载子进程；清理完成前保持忙碌状态。自动更新也有同样的取消入口。取消 AutoMAA 下载后，本次打开期间不会自行重新下载；手动点击下载或再次开启自动下载可以恢复。关闭 MAA 自动更新开关只影响后续自动更新，当前操作通过“取消更新”停止。确认“重启并立即更新”后，App 替换由更新器完成，不再提供取消按钮。

MAA 下载、校验与启用阶段会写入活动记录。失败详情区分网络、超时与资源不兼容，取消不会记成失败或成功。独立更新失败后可在全局设置手动重试；方案运行前下载失败则保留并校验本地数据，可用时才继续。用户取消方案会停止整个流程，不会跳过更新后继续启动游戏。

## 识别数据与引擎不兼容

AutoMAA 会先在隔离候选目录下载，再让对应 MaaCore 在独立进程中实际加载基础、增量、服务器与 iOS 差异资源。全部通过后才启用；失败或取消保留当前安装。当前安装本身不可用时，会在启动任何游戏客户端前停止。

新数据可能需要新版引擎，或触发引擎的资源加载缺陷。先选择“更新 MAA”；稳定版仍不兼容时，可在更新菜单中确认尝试 Beta，或等待稳定版修复。Beta 不保证解决问题，仍必须通过同样的兼容性校验。AutoMAA 不会自动回退资源或静默改用预发布版，也不会绕过游戏更新提示。

更新范围以 [maa-cli 使用文档](https://docs.maa.plus/zh-cn/manual/cli/usage.html)及[上游命令入口](https://github.com/MaaAssistantArknights/maa-cli/blob/main/crates/maa-cli/src/main.rs)为准。

## 大版本更新后的正确流程

1. 暂时关闭 AutoMAA 定时运行。
2. 手动更新对应游戏 App。
3. 分别启动每个服务器客户端。
4. 等待完整的数据下载和解压，所需时间可能很长。
5. 处理公告、协议更新、重新登录或权限提示。
6. 确认至少能到达登录页或主界面。
7. 在 AutoMAA“全局设置”中检测 MAA 环境，并按需选择“更新 MAA”或“仅更新识别数据”。
8. 在有人值守的情况下运行一次 AutoMAA。
9. 确认稳定后恢复定时。

## AutoMAA 会怎样处理

进入账号或主界面多次失败后，AutoMAA 会结合 MAA 输出判断：

- 游戏版本不匹配；
- 仍在下载或解压数据；
- 服务器维护；
- 登录、认证或用户协议；
- 网络或 MaaTools 连接异常；
- 其他未知界面。

这些情况通常会被标记为“需要手动处理”，然后关闭并跳过当前客户端。后续能够安全启动的客户端仍会继续；如果端口状态无法确认，则停止整个流程。

## MAA 尚未适配新界面

游戏更新后，作战、连战、活动奖励等界面可能先于 MAA 适配。此时：

- 关注 [MAA Releases](https://github.com/MaaAssistantArknights/MaaAssistantArknights/releases) 和已知问题；
- 暂时关闭受影响的 AutoMAA 任务；
- 继续运行已经确认安全的公招、基建等任务；
- 不要通过无限重试强迫 MAA 操作未知界面。

AutoMAA 只能编排 MAA 已支持的能力，不会自行补充画面识别规则。
