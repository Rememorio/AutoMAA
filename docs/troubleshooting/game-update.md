# 游戏更新与人工处理

游戏包体、资源数据和 MAA 识别资源是三个不同层级：

| 内容 | 谁负责更新 |
| --- | --- |
| 游戏 App 包体 | 用户在当前游戏运行环境中手动更新 |
| 游戏首次启动的数据下载与解压 | 游戏客户端，由用户等待和确认 |
| MaaCore 与基础资源 | `maa-cli` / AutoMAA“更新核心与基础资源”，或全局设置中的空闲自动更新 |
| 可独立更新的识别资源 | `maa-cli` / AutoMAA“热更新识别资源” |
| AutoMAA App | AutoMAA 应用内更新；必要时从本项目 GitHub Releases 手动安装 |

AutoMAA 不会下载游戏包体，也不会绕过版本提示或未知更新界面。

核心更新会安装稳定版 MaaCore 及随包基础资源；方案的运行前热更新只获取上游单独发布的识别资源。建议保留需要及时识别新界面的方案热更新，并按需开启全局核心自动更新；两个入口都会避让正在运行的方案。

## 大版本更新后的正确流程

1. 暂时关闭 AutoMAA 定时运行。
2. 手动更新对应游戏 App。
3. 分别启动每个服务器客户端。
4. 等待完整的数据下载和解压，所需时间可能很长。
5. 处理公告、协议更新、重新登录或权限提示。
6. 确认至少能到达登录页或主界面。
7. 在 AutoMAA“全局设置”中检测 MAA 环境，并按需更新核心、基础资源与识别资源。
8. 在有人值守的情况下运行一次 AutoMAA。
9. 确认稳定后恢复定时。

## AutoMAA 会怎样处理

进入账号或主界面多次失败后，AutoMAA 会结合 MAA 输出判断：

- 游戏版本不匹配；
- 仍在下载或解压数据；
- 服务器维护；
- 登录、认证或用户协议；
- 网络或 MaaTools 连接异常；
- 其他未知界面。

这些情况通常会被标记为“需要手动处理”，然后关闭并跳过当前客户端。后续能够安全启动的客户端仍会继续；如果端口状态无法确认，则停止整个流程。

## MAA 尚未适配新界面

游戏更新后，作战、连战、活动奖励等界面可能先于 MAA 适配。此时：

- 关注 [MAA Releases](https://github.com/MaaAssistantArknights/MaaAssistantArknights/releases) 和已知问题；
- 暂时关闭受影响的 AutoMAA 任务；
- 继续运行已经确认安全的公招、基建等任务；
- 不要通过无限重试强迫 MAA 操作未知界面。

AutoMAA 只能编排 MAA 已支持的能力，不会自行补充画面识别规则。
